Overview

GPU times come from per-queue timestamps; busy time counts the moments some queue ran a pass, span runs from the first timestamp to the last.

GPU timeline

One lane per queue. Brackets above a lane are its submissions; arrows are cross-queue waits (from the end of the submission waited for to the start of the waiting one); shaded bands are where both queues ran passes at once.

Wheel to zoom, drag to pan, double-click to fit. Click a pass to inspect it.

Where the commands run in the GPU pipeline

Each captured command maps to the pipeline stages and hardware units it occupies: dispatches to the shader cores, ray dispatches to ray generation, the ray tracing units' traversal and the hit / miss shaders, copies to the copy path, and barriers and queue waits to the command processor. Select a pass to light up its stages.

Stages per pass

Commands per stage; the commands a queue executes between two of its passes (waits, barriers) count for the pass after them.

Submissions & barriers

The render graph's schedule: every submission with the submissions of other queues it waits for, and every barrier with the stages it waits for and the stages it unblocks (from its before and after states).

Memory

Transient resources live in one placed heap per frame and share memory when their lifetimes do not overlap. Persistent resources are sub-allocated from the allocator's heaps; each heap is drawn to its own scale, every resource at its offset.

Transient heap over the frame

Columns are the live passes in submission order, rows the heap offset. Rectangles stacked at the same offset with disjoint columns are aliased: the same memory reused.
